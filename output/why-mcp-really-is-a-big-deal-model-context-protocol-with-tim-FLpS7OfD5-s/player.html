Tóm tắt

Tim Berglund explains why Model Context Protocol (MCP) is a big deal for building agentic AI applications professionally. Most people focus on enhancing desktop apps with AI, but MCP offers a broader vision: a standard way for LLMs to access tools (actions) and resources (data) beyond the foundation model. He walks through how LLMs work: prompt in, response out — but agentic AI needs to invoke tools and fetch external data (files, databases, Kafka topics). MCP architecture: a host application uses an MCP client to connect to MCP servers. Each server exposes tools, resources, and prompts in a discoverable way. Connection can be stdio or HTTP/SSE with JSON-RPC. Example: an appointment service needs calendar integration, restaurant/coffee shop listings — instead of baking all that into the agent, MCP lets you plug in servers. Workflow: user prompt → client asks server for capabilities → gets resource list → LLM decides which resources to fetch → client fetches → LLM interprets. For tools, foundation model APIs accept tool descriptions; the LLM recommends invocations but the client executes (no Skynet). Key benefits: pluggability, discoverability, composability — servers can be clients of other servers (e.g. Confluent MCP for Kafka). MCP is a gateway to true agentic AI in the enterprise.
